# Metrics

`[metrics] enabled = true` serves Prometheus text on `GET /metrics`, on the S3
port or on `[metrics] listen_addr`. Code records through the [`metrics`]
facade, a no-op until the binary installs its recorder.

Each crate declares the metrics it records in a `METRICS` table
(`pigeonhole_blob::METRICS`, `pigeonhole_meta::METRICS`,
`pigeonhole::state_metrics::METRICS`). The help text in the scrape comes from
it, and so does the list below: `tests/metrics_doc.rs` fails when the list is
stale and rewrites it with `UPDATE_METRICS_DOC=1`.

## Watching them live

```sh
brew install prometheus grafana awscli
make metrics-demo                     # ./scripts/metrics-demo.sh up
open http://127.0.0.1:3000/d/pigeonhole/pigeonhole
./scripts/metrics-demo.sh check       # every panel's query answers; every exported metric is listed here
make metrics-demo-down                # data stays in .cache/metrics-demo; `metrics-demo.sh clean` drops it
```

`up` builds the release binary and starts, each logging to `.cache/metrics-demo/`:

| What | Where |
|---|---|
| pigeonhole, blobs and log on local disk | S3 `127.0.0.1:8333`, `/metrics` on `127.0.0.1:9100` |
| Prometheus, scraping every 2 s (`ops/observability/prometheus.yml`) | `127.0.0.1:9090` |
| Grafana, anonymous admin, the dashboard provisioned | `127.0.0.1:3000` |
| `scripts/metrics-load.sh`: PUT / multipart / GET / ranged GET / HEAD / LIST / COPY / DELETE in a loop (`NO_LOAD=1` skips it) | |

The dashboard is generated: edit `ops/observability/dashboard.py`; `up`
writes `ops/observability/grafana/dashboards/pigeonhole.json` from it (commit
both). The JSON imports into any Grafana with a Prometheus data source of
uid `prom`.

## Reading them

- `pigeonhole_gateway_request_duration_seconds` is the time to response
  headers: a GET's body streams after it, see `pigeonhole_bytes_to_clients_total`
  for how much went out.
- Bytes are counted as body frames pass, not from `Content-Length`: a HEAD
  sends nothing, an aborted download counts what left.
- `pigeonhole_instance_call_duration_seconds{op="get"}` stops when the stream
  starts; the time to read it is in the caller's.
- Buckets: `*_seconds` from 100 µs to 5 min, `*_ratio` 0.01…1.05,
  `*_per_chunk` / `*_per_entry` 1…1024 (`crates/bin/pigeonhole/src/prometheus.rs`).
- The tablet gauges (`pigeonhole_s3_*`, `pigeonhole_chunk*`,
  `pigeonhole_meta_*_position`) are refreshed every 5 s, each refresh a pass
  over the state.
- Label values are bounded: S3 operation names, store ids from the config,
  chat method names.

Queries worth having:

```promql
# S3 requests/s by operation, and their p99
sum by (op) (rate(pigeonhole_gateway_request_duration_seconds_count[1m]))
histogram_quantile(0.99, sum by (le, op) (rate(pigeonhole_gateway_request_duration_seconds_bucket[5m])))
# Hit ratio per cache level
sum by (level) (rate(pigeonhole_cache_requests_total{outcome!="miss"}[5m]))
  / sum by (level) (rate(pigeonhole_cache_requests_total[5m]))
# What the chats make us wait
sum by (service, method) (rate(pigeonhole_backend_throttle_wait_seconds_sum[5m]))
# Entries in the log since the last snapshot
pigeonhole_meta_applied_position - pigeonhole_meta_base_position
```
